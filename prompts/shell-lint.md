# Shell & Bash Command Hook Guidance (Template Override)

Use this guidance when the rule targets shell/CLI behavior: command blocking (rm -rf, chmod 777, curl piping), command chaining, data exfiltration, environment exposure, pipeline complexity, or dangerous flags.

Routing boundary:
- Use `security-layer2.md` for code-level `process.env` enumeration and sensitive file/path string references.
- Use `simple-regex.md` for API key/token literal patterns in source code.

**This is a template-override specialist.** Use the template below instead of the standard Step 2 template.

## Template

Shell hooks must check BOTH direct Bash tool commands AND shell code written to files:

```python
#!/usr/bin/env python3
"""
Hook: [brief description]
Rule: [the user's rule]
Generated by steer
"""

import json
import sys
import re

def main():
    try:
        stdin_data = sys.stdin.read()
        if not stdin_data.strip():
            sys.exit(0)
        data = json.loads(stdin_data)
    except (json.JSONDecodeError, Exception):
        sys.exit(0)

    tool_name = data.get('tool_name', '')
    tool_input = data.get('tool_input', {})

    if tool_name == 'Bash':
        content_to_check = tool_input.get('command', '')
        file_path = ''
    elif tool_name in ('Edit', 'MultiEdit', 'Write'):
        file_path = tool_input.get('file_path', '')
        if tool_name == 'MultiEdit':
            edits = tool_input.get('edits', [])
            content_to_check = '\n'.join(e.get('new_string', '') for e in edits)
        else:
            new_string = tool_input.get('new_string', '')
            content = tool_input.get('content', '')
            content_to_check = new_string or content or ''
    else:
        sys.exit(0)

    if not content_to_check.strip():
        sys.exit(0)

    # [FILE TYPE FILTER] - ONLY apply to file tools, never filter Bash commands!
    # Bash tool has file_path='', so any endswith() check will exit early and skip it.
    # Example:
    #   if tool_name != 'Bash' and not file_path.endswith(('.sh', '.bash', '.zsh', '.fish')):
    #       sys.exit(0)
    # [DETECTION LOGIC] - Check content_to_check against rule

    sys.exit(0)

if __name__ == "__main__":
    main()
```

**When the rule ONLY targets Bash tool commands** (not file content), simplify by filtering to just the Bash tool:

```python
    if tool_name != 'Bash':
        sys.exit(0)

    command = tool_input.get('command', '')
    if not command.strip():
        sys.exit(0)

    # [DETECTION LOGIC]
```

## File Types for Code Analysis

When checking file content (Edit/MultiEdit/Write), filter to shell-related files:
`.sh`, `.bash`, `.zsh`, `.fish`, `Dockerfile`, `*.dockerfile`, `.yml`/`.yaml` (run: blocks), `Makefile`/`*.mk`

## Detection Strategies

### Command-Position Matching (critical for command-blocking rules)

When a rule blocks *invoking* a command (as opposed to a dangerous flag pattern), match the token only at **command position** — the first word of a command segment — never anywhere in the line. Argument-position mentions are prose, not invocations: `git commit -m "switch from python to rust"` and `echo python is fun` must not block a rule against bare `python`.

- Split each line into segments at `; & | ( ) \`` and `$(`; check each segment's first token after skipping `VAR=value` assignments, command wrappers (`sudo`, `env`, `time`, `nohup`, `xargs`, `exec`, ...), and wrapper flags.
- **Skip heredoc bodies.** Text between `<<DELIM` (or `<<-DELIM`, `<<'DELIM'`) and the closing delimiter line is data — commit messages, file content — not commands. Track opened delimiters per line and skip lines until each closes. A blocked `git commit -F- <<'EOF' ...` whose message merely *mentions* the command is the #1 real-world false positive for this rule class.
- Negative tests MUST include: the token quoted in a string, the token in argument position unquoted (`echo <token> is fun`), and the token inside a heredoc body at line start.

### Exact Command Blocking
```python
# Block specific commands (e.g., rm -rf)
if re.search(r'\brm\s+(-[a-zA-Z]*r[a-zA-Z]*f|--recursive\s+--force|-[a-zA-Z]*f[a-zA-Z]*r)\b', command):
    # block
```

### Dangerous Flag Detection
```python
# Block chmod with overly permissive modes
if re.search(r'\bchmod\s+[0-7]*7[0-7]{2}\b', command):
    # block
```

### Pipe-to-Execution Blocking
```python
# Block curl/wget piped to shell
if re.search(r'(curl|wget)\s+.*\|\s*(bash|sh|zsh|python|perl|ruby)', command):
    # block
```

### Sudo Escalation
```python
# Block sudo with certain commands
if re.search(r'\bsudo\s+(rm|chmod|chown|dd|mkfs|fdisk)\b', command):
    # block
```

### Command Chaining (semicolons)
```python
def has_command_chaining(content):
    for line in content.splitlines():
        stripped = line.strip()
        if not stripped or stripped.startswith('#'):
            continue
        if ';' in stripped:
            # Allow structural: if/while/for...;then/do
            if re.search(r'(if|while|for|until)\s+.*;\s*(then|do)$', stripped):
                continue
            if re.search(r'\)\s*;\s*$', stripped):  # case patterns
                continue
            return True
    return False
```

### Data Exfiltration (piping to network tools)
```python
# command | curl/wget with upload flags
r'.+\|\s*(curl|wget)\s+.*(-d|--data|--post-data)'
```

### Environment Command Detection
```python
# Standalone `env` command (not `env VAR=value command`)
if re.match(r'^env(\s|$)', stripped) and not re.match(r'^env\s+\w+=', stripped):
    # block
```

## CRITICAL: Legitimate vs Dangerous Shell Constructs

### DO NOT block (structural semicolons):
```bash
if [ -f "file" ]; then echo "found"; fi
for item in *.txt; do echo "$item"; done
while read line; do process "$line"; done
```

### DO block (command chaining):
```bash
echo "start"; rm -rf /tmp/*; echo "done"
```

## False Positive Avoidance

- **echo/print context**: `echo "rm -rf example"` is not dangerous — the command is inside a string being printed, not executed. Check if the match is inside quotes following `echo`, `printf`, or a comment.
- **Dry-run flags**: Commands with `--dry-run`, `-n` (for rm), or `--no-clobber` may be safe variants. Consider whether the rule intends to block these.
- **Variable assignment**: `CLEANUP_CMD="rm -rf /tmp/build"` assigns a string, doesn't execute it. For simple rules, allow assignment; for strict rules, flag it.
- **Comments**: Shell comments include BOTH full-line (`# comment`) AND inline (`cmd # comment`). A naive `startswith('#')` check misses inline comments. Before running detection regex, strip comments from each line:

```python
def strip_shell_comments(line):
    """Strip shell comments while preserving # inside quotes and shebangs."""
    if line.strip().startswith('#!'):
        return line  # shebang
    in_single = False
    in_double = False
    for i, ch in enumerate(line):
        if ch == "'" and not in_double:
            in_single = not in_single
        elif ch == '"' and not in_single:
            in_double = not in_double
        elif ch == '#' and not in_single and not in_double:
            return line[:i]
    return line
```

Use this per-line before applying detection patterns. This prevents false positives on `rm -rf /tmp/cache  # cleanup note` while preserving `#` inside quoted strings like `echo "color is #ff0000"`.

## Self-Test Patterns

**Positive tests (MUST block) — always test via Bash tool:**
```bash
echo '{"tool_name":"Bash","tool_input":{"command":"rm -rf /"}}' | python3 hook.py
```

**Negative tests (MUST allow):**
```bash
# Safe variant of the same command family
echo '{"tool_name":"Bash","tool_input":{"command":"rm file.txt"}}' | python3 hook.py

# Irrelevant tool
echo '{"tool_name":"Write","tool_input":{"file_path":"test.py","content":"print(1)"}}' | python3 hook.py
```

**Boundary negative tests (the hard ones):**
```bash
# Command appears in echo/comment context
echo '{"tool_name":"Bash","tool_input":{"command":"echo \"never run rm -rf /\""}}' | python3 hook.py
```
