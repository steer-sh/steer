# Changelog

## Unreleased

### Features

- **The evidence root leaves `~/.claude`**: every corpus — the adjudication ledger, the report queue, the session snapshots, the denial rows — now lives under `~/.steer/state/`. The ledger is the record of steer's own decisions and it outlives the transcripts it was measured over, so it cannot sit inside one harness's config directory: cadence is the one hook the Codex plugin bundles and it fired on a fresh machine, so installing steer in Codex and opening one session created `~/.claude` on a machine that had never run Claude Code — and the obvious remedy, deleting the strange directory, destroyed every verdict steer ever measured. The move copies and never deletes, so an older steer binary still finds the corpus, and a machine that has not migrated keeps reading the legacy root. A migrated component is marked last, so an interrupted copy is retried whole. Only steer's own components move; another tool's state directory beside them is left alone.

- **`steer hooks rebuild`**: the master hook now carries the provenance of the runtime spliced into it — a digest of that runtime plus the steer that wrote it — and one command regenerates it and re-registers it in every target harness. A store keeps whatever runtime it was last built with, so a master written by an older steer records fewer audit fields than the scorer joins on, and upgrading the CLI repaired nothing because nothing rewrote the master. Regeneration alone is not enough: consolidation writes to the neutral store, migration deliberately leaves the legacy files in place for older binaries, and the harness keeps naming the legacy path — so the repaired master would sit unused. `steer status` reports each registered master as `current`, `stale` or `unknown` (an unstamped master never reads as current), the SessionStart cadence nudges once per distinct staleness, and the dashboard rebuilds with `b`. `steer verify` no longer consolidates: verifying files is a read, and doing so migrated a store and stranded its registration.

- **Codex plugin distribution**: `codex plugin marketplace add steer-sh/steer-skill` then `codex plugin add steer@steer-marketplace` installs steer natively. `.codex-plugin/plugin.json` names the two skills and the bundled hook; the `/steer` skill moved from the repository root to `skills/steer/`, because Codex refuses the plugin root as a skill root — and skills.sh stops at a root SKILL.md, so before the move it distributed `/steer` alone and never shipped `/steer-report`; `.agents/plugins/marketplace.json` is the Codex marketplace beside the Claude Code one. The three manifests describe one plugin and a test pins them to each other, because Codex copies a plugin root verbatim and a field that disagrees installs one plugin under two identities. The bundled `SessionStart` cadence command reads `PLUGIN_ROOT` and falls back to `CLAUDE_PLUGIN_ROOT`, so one `hooks/hooks.json` serves both harnesses; both skills resolve the bundled CLI the same way. The plugin bundles cadence only — the commit gate and the generated guards stay explicit activations, and Codex trusts no plugin hook until it is reviewed in `/hooks`.

- **Universal guard runtime**: The master hook normalizes a harness payload into per-file virtual edits before running any guard — a Claude `MultiEdit` becomes one edit per hunk, and a Codex `apply_patch` becomes one edit per file in the patch. Every guard runs against every affected file, and the first block wins. A block is rendered in the harness's own contract: `decision: block` for Claude Code, `hookSpecificOutput.permissionDecision: deny` for Codex (`--harness codex`). Guards themselves are unchanged.

- **Familiar language on every surface**: steer explains its work in words a reader already has — review, finding, problem, fix, guard, result. Terminal, HTML and the dashboard printed the raw verdict token (`class-faded`, `legacy-unscoped`, `evidence-incomplete`); they now print a label from one table in `internal/status/action.go`, alongside a section heading that names an object and a sentence that names the action. `--json` still carries the token, so a person and a skill reading the snapshot share one word. A label states a direction only where the scorer crossed a bound and claimed one; anywhere else a word like "fewer" would state the claim the scorer withheld. `evidence-incomplete` now names which of its four causes applies and offers `steer commit-gate backfill` only for the one that command repairs. `/steer-report` reads tokens and speaks labels, proposes each fix by answering what keeps happening, what supports it, what would change, what it could cost and what decision is needed — and six saved scenarios under `tests/scenarios/` regenerate that prose for a person to judge.

- **`steer fix`**: the command tree formerly named `steer intervention`, which stays as an alias. `--tier` is validated for the first time, against the union of both live ladder spellings (`check|steer|prose|prompt` and `check|guard|instruction|review`), held once in `internal/tier` and read by the display phrase, the removal phrase and the guard-scope rule alike. Before this, three readers enumerated their own spellings and nothing validated: a typo tier fell through every one and rendered as itself.

- **`steer intervention`**: the intervention command set — `match`, `register`, `reject`, `scope`, `score`, `list`, `retire` — under a corpus-neutral name. `steer commit-gate mine` is the same set under its original name and is unchanged; both trees come from one factory. A record now names the corpus it is counted over and the unit that corpus counts by, and one registry decides which records this engine can score: a record from another corpus is carried unscored rather than counted against evidence it was never authored over.

- **Scope v2 — a harness predicate**: `--scope-harness` names the exact harness ids a class is measured on, AND'd with `--scope-repo` and `--scope-path`. A guard installed in only one harness is scored over only that harness's evidence. `harness` also joins the confound categories, so a class measured on Claude Code before and Codex after reports `confounded` rather than a verdict. A scope naming no harness is still written as v1, so every existing record and every older binary is untouched.

- **`steer commit-gate`**: a panel of independent reviewers red-teams a change's diff before it lands, blocking while a finding stands and writing an adjudication row for every decision. Three channels share one engine — `commit-gate review` (Claude Code PreToolUse), `commit-gate review-codex` (Codex PreToolUse), and `commit-gate precommit` (git hook) — with agy, Codex and `claude -p` as reviewer providers. `install --harness codex` preserves unrelated `hooks.json` keys and reports the manual trust step; `remove` and `status` cover both harnesses. New ledger rows identify their client and harness without invalidating the existing corpus.

- **`/steer-report` skill**: Mines recent Claude Code transcripts and CLAUDE.md for recurring friction (repeated user corrections, rejected tool calls, lint/test failures, unenforced CLAUDE.md directives) and proposes evidence-backed steer hooks. Recommends a fresh session when invoked mid-conversation; `--headless` emits candidates as JSON without creating hooks.
- **`steer report` CLI command**: Streaming transcript scanner behind the skill. Scans `~/.claude/projects` over a look-back window (`--days`, default 30; all projects by default, `--project-only` to narrow) and emits a versioned, size-capped JSON digest (`--max-digest-bytes`, default 40KB) — lowest-scoring clusters are evicted to fit, and `stats.truncated` reports honesty. Pure JSON on stdout, progress on stderr.
- **Audit log**: Every hook block appends a JSON line to `.steer/hooks/steer-audit.jsonl` (`timestamp`, `rule`, `hook_name`, `enforcement`, `harness`, `session_id`, `thread_id`, `repository`, `file_path`, `tool_name`, `snippet`) — the artifact a team lead reads to answer "what did steer stop this week"
- **Team policy in git**: `steer team lock` writes a repo-committed lockfile with embedded hook content and integrity hashes; `steer team apply` reconciles a clone against it (floor semantics by default, `--force` for strict match, `--dry-run` to preview); `steer team verify --ci` fails pipelines on drift
- **Shared reconcile engine**: `steer preset sync` and `steer team apply` now run on one drift-detection/repair core

### Fixes

- **Shell structure has one Go parser**: the commit gate and report classifier now read Bash structure through `mvdan.cc/sh/v3/syntax` instead of maintaining independent quote, separator, substitution, redirection, and heredoc scanners. Exact commit recognition covers subshells, command substitutions, wrappers, quoted Git options, `-C`, `--work-tree`, staging pathspecs, `-m`, `-F`, and punctuation-bearing heredocs. The gate retains its permissive detector as a conservative backstop; loose-only or dynamically located commits are refused with an explicit retry instead of being assigned a guessed repository or message. The gate engine identity and report parser digest both move at this population boundary.

- **A command that PRINTS a failure did not FAIL**: the friction classifier matched lint, test and compile patterns against the output of any shell call, so `cat` over a Go file full of `fmt.Errorf("failed to …")`, `sed -n` over a note about a failed approach and `ls` over a directory holding `eslint.config.mjs` all counted as tool failures. Measured over 30 days and both harnesses, 22 of the 24 clusters reaching the 3-session threshold were a file read — noise at exactly the threshold an intervention freezes its baseline over, and the snapshot store shares the classifier, so it stored the same misclassification for the scorer. A signal now needs a command that RUNS a program: steer reads the verb of every pipeline segment past a heredoc body, an assignment and a wrapper, against an allowlist of build, test and lint verbs plus any script the shell executes itself. The match must also sit outside a quoted string, so the message inside `fmt.Errorf(…)` is the source it belongs to rather than a failure. Two clusters survive at that threshold and both are real. Gating on the exit status instead was measured and rejected: `./check.sh 2>&1 | tail -30` exits as `tail` does, so it drops the real failures and keeps the commit gate quoting its own review prose back. `report.ParserInstrument()` changes, so every stored snapshot reads as instrument drift rather than as a moved rate.

- **A documentation heredoc fired the commit gate**: the commit detector scanned raw command text, so writing prose that quotes `git commit` — `cat > doc.md <<'EOF' ... EOF` — opened a review chain over a change that commits nothing. Both harnesses share the detector, so this was never Codex behavior. The body of a quoted heredoc now leaves the span scan when the segment writes its stdin to a file and pipes nothing onward — `cat` with a redirect, or `tee` naming the file it writes. Everything else stays in the scan, because it can still execute the body: `bash <<'EOF' > log.txt` redirects to a file and runs the body, `cat <<'EOF' | bash` hands it to a shell, and `tee log.txt <<'EOF' | bash` does both.

- **The commit-gate resolver was Claude Code's alone**: the join engine that reconciles a ledger row against the agent's self-reported adjudication lived inside the Claude Code adapter, so Codex rows could never resolve and the scorer withheld on them forever. The engine now lives in `internal/gate/resolve`, reads only normalized ledger messages, and takes one harvest per harness. Codex installs register the resolver on both Stop and SubagentStop, since a gate that fires inside a subagent is adjudicated there. The join key is a row's thread where it has one, so two subagent threads of one session cannot claim each other's ledger.

- **The Codex commit gate never fired**: the adapter matched `tool_name: "exec_command"` and read `tool_input.cmd`, while Codex reports `Bash` and `tool_input.command` for every shell path. The registered matcher was `exec_command` too, so the hook was not even invoked. Both now use `Bash`, the legacy names are still accepted on input, and `status` names a legacy registration as inert. A Codex subagent's calls key their chain on `agent_id` — its own rollout thread — so two threads of one session no longer share a firing cap, and rows carry the Codex author model, task and rollout the way Claude Code rows do. Denials use `hookSpecificOutput.permissionDecision: deny`.

- **settings.json round trip dropped keys on the innermost hook object**: registering or removing a steer hook rewrote every PreToolUse hook through a closed struct modeling only `type`, `command` and `timeout`, so any other key on a neighbouring hook — `statusMessage`, or anything Claude Code adds later — was silently lost. `CommandHook` and `HookEntry` now carry unmodeled keys through unchanged, the way the top level and the hook-event level already did. The commit gate's own hook gains a `statusMessage`.

- **Consolidation drops module-level constants**: `steer register` consolidation extracted `main()` and helper functions but silently dropped top-level assignments (e.g. compiled regexes), producing a master hook whose `NameError` was swallowed at runtime — the hook passed individual self-tests but enforced nothing. Constants are now carried into the master with prefixed names; the steer skill additionally verifies the consolidated master after registration.

### Security

- Self-protection hook now guards `steer-audit.jsonl` (a blocked agent can't erase its audit trail) and `steer-team.lock.json` (`steer team lock` is the sanctioned writer); `steer team` commands are classified as trusted reconcile paths
- Self-protection hardening: protected-path scan now runs before steer-CLI classification, and mutating commands are detected anywhere in a compound command — closes `rm steer-hooks.py; steer preset sync` style evasions

## v1.0.0

Initial release.

### Features

- **`/steer` skill**: Generate Claude Code hooks from natural language rules with automatic self-testing
- **Rule syntax**: `detect | suggest` — left side defines what to block, right side provides developer guidance
- **Hard + soft steering**: Hook-level enforcement (hard) paired with `CLAUDE.md` rule persistence (soft)
- **Steer CLI**: Full hook lifecycle management — `register`, `remove`, `list`, `test`, `verify`
- **Factory preset pack**: 12 security hooks shipped as built-in presets (`steer preset enable-bundle security`)
- **Self-protection hook**: Factory hooks guard their own persistence — agent can't disable or overwrite them
- **Git enforcement**: `steer verify --staged` for pre-commit checks, `steer git-hooks install` for automation
- **CI support**: `steer verify --changed --base <ref> --head <ref>` for pull request gates
- **Upsert-by-default registration**: `steer register` always succeeds — no interactive prompts, safe for agent workflows
- **Cross-platform**: Prebuilt binaries for macOS (amd64/arm64), Linux (amd64/arm64), Windows (amd64)
- **Standalone installer**: `install-prebuilt.sh` for CLI use outside the plugin system
